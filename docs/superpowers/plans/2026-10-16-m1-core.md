# Likeminded Portfolio M1 (Core) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the first live version of the portfolio: site skeleton with all ten modules in the navigation, a tested matching engine with an in-browser Match Simulator, the Overview page driven by computed metrics, and ADR-001/ADR-002.

**Architecture:** Astro static site with React islands. All logic lives in pure TypeScript under `src/domain/` (no UI imports) and is unit-tested with Vitest; pages and components only call domain functions. Content (ADRs) is MDX validated by Astro content collections; numbers come from one raw-counts file through `metrics.ts`.

**Tech Stack:** Node 24, Astro 7.x, @astrojs/react 7.x, @astrojs/mdx, React 19, TypeScript (strict), Tailwind CSS 4 via `@tailwindcss/vite`, Vitest 5, Playwright 1.6x, @axe-core/playwright.

**Spec:** `docs/specs/2026-10-16-likeminded-portfolio-design.md`

## Global Constraints

- All site copy is in English.
- Static output only: no backend, no accounts, no persistence; interactive state resets on reload and every interactive widget has a Reset button.
- `src/domain/**` must never import from `src/components/**`, `src/pages/**`, React or Astro.
- Matching must never read `User.persona`.
- No percentage is typed by hand anywhere; every percentage comes from `src/domain/metrics.ts`.
- Matching is deterministic: same users + weights → same groups; ties broken by user id (lexicographic).
- Group size is 4–6.
- Every page readable at 375px width with no horizontal scroll.
- Lighthouse performance and accessibility ≥ 90 (checked manually at the end of Task 10).
- The ten modules, in nav order: Overview, Discovery, PRD, Backlog, Wireframes, Prototype, Technical Design, Decision Log, Analytics, Retrospective.

## Review Focus

1. **All similarity weights set to 0** in the simulator → no `NaN` anywhere; scores are 0, the page still renders groups or the empty state. (Task 6, Task 7 tests)
2. **Users with empty interest/book/school lists** → Jaccard of two empty sets is 0, not `NaN`. (Task 6 test)
3. **Diversity slider at 1.0** → groups still satisfy every hard filter and share a slot. (Task 7 test)
4. **Settings under which no group forms** → the simulator shows a message naming the filter that removed the most pairs, never an empty panel. (Task 5 + Task 8 tests)
5. **Phone-width viewing (375px)** → no horizontal scroll on any page, including the simulator. (Task 10 test)

### Task 7: Greedy grouping with reasons

**Files:**
- Create: `src/domain/matching/grouping.ts`, `src/domain/matching/index.ts` (re-exports)
- Test: `tests/unit/grouping.test.ts`

**Interfaces:**
- Consumes: `checkPair`, `sharedSlots`, `topBlockingFilterFor` (Task 5); `pairScore`, `signalSimilarity` (Task 6).
- Produces: `buildGroups(users: User[], w: MatchWeights): MatchResult`; `explainGroup(members: User[]): Reason[]`.

Algorithm (not determined by the signature, so fixed here):

```
1. Sort users by id. Build all compatible pairs (checkPair ok), score them,
   sort by score desc then by "idA|idB" asc.
2. For each pair whose two users are both unassigned:
     group = [a, b]; target = 4 if both prefer "small" else 6
     repeat while group.length < target:
       candidates = unassigned users not in group that pass checkPair with
                    every member AND keep sharedSlots(group+c) non-empty
       if none: break
       fitness(c) = (1 - w.diversity) * mean(pairScore(c, m).score for m in group)
                  + w.diversity * novelty(c)
         where novelty(c) = |c.interests \ ∪group.interests| / max(1, |c.interests|)
       add the candidate with max fitness (ties: smallest id)
     if group.length >= 4: assign members; push Group
3. Every unassigned user → unmatched with reason:
     "No compatible users (most blocked by: <filter>)" where <filter> is
     topBlockingFilterFor(user, allOtherUsers) — or "Not enough compatible
     users for a group of 4" when that returns null.
Group fields: slot = sharedSlots(members)[0]; venueDistrict = most common
member district (ties alphabetical); cohesion = mean pairwise score;
reasons = explainGroup(members).
```

`explainGroup`: for each book/author, interest, school and profession shared by ≥ 2 members, produce `{ signal, text: "<k> of <n> <phrase>" }` (phrases: "read <title/author>", "are into <interest>", "went to <school>", "work as <profession>"); return the top 3 by `k`, ties by text.
